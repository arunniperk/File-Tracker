    Edit `src/FileTracker.App/Services/BackupService.cs`:
    - Add `using System.IO.Compression;`
    - `RestoreFromBackupAsync(string backupFilePath, CancellationToken ct)`:
      1. Throw `FileNotFoundException` if `!File.Exists(backupFilePath)`
      2. Extract to temp dir: `ZipFile.ExtractToDirectory(backupFilePath, tempExtractDir)`
      3. Find the .db file in extracted contents (search for any `.db` file). If none found, throw `InvalidOperationException("Backup file does not contain a database file.")`
      4. Validate the backup .db is a valid SQLite database: open a temporary `SqliteConnection` to it, run `PRAGMA integrity_check`, dispose the connection. If validation fails, throw `InvalidOperationException($"Backup database is corrupted: {integrityResult}")`
      5. Get current DB path from `_db.DataSource`
      6. Get attachments path: `Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData), "FileTracker", "attachments")`
      7. Copy the backup .db file over the current database: `File.Copy(backupDbPath, _db.DataSource, overwrite: true)` — the SQLite connection should be closed or at least the file overwrite should succeed (WAL mode means -wal and -shm files may exist alongside .db; delete those too before copy if they exist)
      8. For attachments: if backup contains `attachments/` directory, delete the current attachments directory (if exists), then copy the backup attachments directory recursively
      9. Log: `_logger.LogInformation("Restore completed from backup: {Path}", backupFilePath)`
      10. Note: the caller (MainViewModel) must restart the app after this — per D-05. The service does NOT restart the app itself.
    - Safety checks per D-04: the WARNING CONFIRMATION is done at the ViewModel level, not the service. The service does the restore; the ViewModel presents the confirmation dialog.

    Edit `src/FileTracker.App/Services/BackupService.cs`:
    - `CheckDatabaseIntegrityAsync(CancellationToken ct)`:
      1. Run `PRAGMA integrity_check` on `_db` (the current SqliteConnection)
      2. `PRAGMA integrity_check` returns a single row with a single column: "ok" if healthy, or a list of error messages
      3. If result is "ok", return `new IntegrityCheckResult { IsOk = true, Message = "ok" }`
      4. If result is anything else (error messages), return `new IntegrityCheckResult { IsOk = false, Message = resultString }`
      5. Per D-10: log the result via Serilog — `_logger.LogInformation("Database integrity check: {Result}", integrityResult.IsOk ? "PASS" : "FAIL - " + integrityResult.Message)`
      6. Use `ct.ThrowIfCancellationRequested()` before the PRAGMA call

<threat_model>
## Trust Boundaries

| Boundary | Description |
|-----------|-------------|
| Backup .zip file → RestoreFromBackupAsync | Untrusted backup file could be malicious or corrupted |
| Startup → DatabaseInitializer.IntegrityCheckAsync | DB state unknown on startup |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering | RestoreFromBackupAsync (backup .zip) | mitigate | Validate .db inside .zip via PRAGMA integrity_check before replacing current DB |
| T-04-05 | Elevation of Privilege | RestoreFromBackupAsync (file overwrite) | mitigate | Only overwrites known paths (DB at _db.DataSource, attachments in LocalAppData/FileTracker/attachments); no path traversal |
| T-04-06 | Denial of Service | RestoreFromBackupAsync (large .zip) | accept | Zip extraction bounded by local disk; no remote attack vector |
| T-04-07 | Tampering | DatabaseInitializer.IntegrityCheckAsync | mitigate | PRAGMA integrity_check is a SQLite built-in; result used before any data operations |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages — all APIs are built-in .NET |
</threat_model>
