Create the Positions table with default seed data (D-05), a PositionRepository with full CRUD, a PositionService with validation, and a ManagePositionsWindow allowing staff to add, rename, reorder, and deactivate officer positions.

Output: Working Manage Positions window showing default hierarchy with add/rename/reorder/deactivate capability. Active positions available via `IPositionService.GetActiveAsync()` for Plan 02-03 dropdowns.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | ManagePositionsWindow text input | mitigate | PositionService.AddAsync validates name is not null/empty/whitespace before INSERT |

| T-02-04 | Repudiation | Position deactivation | accept | Single-user desktop app. Deactivation is a soft-delete (row preserved). No audit trail needed for position changes — they are configuration, not document records |
| T-02-05 | Elevation of Privilege | Position management access | accept | Single-user desktop app — user is the sole operator. No role-based access control |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages in this phase. All dependencies carried forward from Phase 1 audit |
