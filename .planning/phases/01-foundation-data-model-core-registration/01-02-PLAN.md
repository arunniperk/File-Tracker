    2. IDocumentRepository.cs — add interface method:
       `Task<int> GetNextSequenceAsync(int year, IDbTransaction transaction)`
       The `transaction` parameter ensures the sequence increment is part of the same transaction as the document INSERT.

    3. DocumentRepository.cs — implement GetNextSequenceAsync:
       Use SQLite UPSERT RETURNING as a single atomic SQL statement:
       ```sql
       INSERT INTO TrackingSequence (Year, LastNumber)
       VALUES (@Year, 1)
       ON CONFLICT(Year) DO UPDATE SET LastNumber = LastNumber + 1
       RETURNING LastNumber;
       ```
       Execute via `_db.QuerySingleAsync<int>(sql, new { Year = year }, transaction)`
       The `RETURNING` clause returns the new LastNumber directly — no separate SELECT needed.

    4. DocumentService.cs — integrate tracking ID into RegisterAsync:
       a. Add private method `async Task<string> GenerateTrackingIdAsync(int year)`:
          - Calls `await _repository.GetNextSequenceAsync(year, transaction)` where `transaction` is the SAME transaction used for document INSERT
          - Formats: `return $"{seq:D4}/{year}"` — produces "0001/2026"
       b. Modify RegisterAsync(dto):
          - After validation, begin transaction
          - Call `GenerateTrackingIdAsync(dto.DocumentDate.Year)` within the same transaction
          - Pass trackingId to `dto.ToEntity(trackingId)`
          - Insert document within same transaction
          - Commit transaction (both sequence + document succeed or both roll back)
       c. Exception handler: rollback on any failure — tracking ID is NOT consumed if document save fails

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Radio button toggle → ViewModel | Untrusted UI state changes direction routing |
| Form input → ObservableValidator | Validation attributes gate entry to service layer |
| Tracking ID generation → SQLite | Atomic UPSERT RETURNING prevents race conditions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering | Tracking ID race condition (two concurrent saves) | mitigate | SQLite `ON CONFLICT...DO UPDATE...RETURNING` single atomic statement — no read-then-write gap |
| T-01-07 | Tampering | Tracking ID consumed but document not saved | mitigate | Both in same `IDbTransaction` — rollback restores sequence state |
| T-01-08 | Tampering | Form submitted with invalid direction | mitigate | ObservableValidator + `[Required]` attributes block submit when fields empty. Direction derived from radio state, not user string input |
| T-01-09 | Tampering | Duplicate original file number | mitigate | UNIQUE constraint on OriginalFileNumber column (Plan 01). Service catches SqliteException and displays error to user |
| T-01-10 | Repudiation | User claims "I didn't mean to discard" | accept | D-11 dialog is the agreed mitigation. User explicitly confirms discard. No further non-repudiation needed for Phase 1 |
</threat_model>
