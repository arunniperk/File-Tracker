**AttachmentService** (src/FileTracker.App/Services/AttachmentService.cs):

Constructor: `(IDocumentRepository docRepo, IAttachmentRepository attachmentRepo, ILogger<AttachmentService> logger)`.

`_attachmentRoot` — computed once: `Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData), "FileTracker", "attachments")`.

AddAttachmentAsync(documentId, sourceFilePath):
1. Validate documentId exists via docRepo.GetByIdAsync → NotFoundException if null
2. Validate extension: `Path.GetExtension(sourceFilePath).ToLowerInvariant()` must be `.pdf`, `.jpg`, `.jpeg`, or `.png` → ArgumentException otherwise
3. Validate file size: `new FileInfo(sourceFilePath).Length` must be ≤ 10_485_760 (10MB) → ArgumentException otherwise
4. Construct storage path: `{_attachmentRoot}\{documentId}\` — call `Directory.CreateDirectory`
5. Generate unique filename: `$"{DateTime.Now:yyyyMMdd_HHmmss}_{Path.GetFileName(sourceFilePath)}"`
6. Copy file: `File.Copy(sourceFilePath, destPath, overwrite: false)`
7. Insert DB record with the storage path, original filename, file size, and MIME type derived from extension
8. On DB failure (exception), clean up the copied file in a try/catch — but DON'T rethrow the cleanup exception

Detect MIME type from extension: `.pdf` → `application/pdf`, `.jpg`/`.jpeg` → `image/jpeg`, `.png` → `image/png`.

GetAttachmentsAsync(documentId): delegates to attachmentRepo.GetByDocumentIdAsync.

RemoveAttachmentAsync(attachmentId):
1. Get attachment via attachmentRepo.GetByIdAsync → NotFoundException if null
2. Delete the physical file if it exists (`File.Delete` wrapped in try/catch — don't fail if file already gone)
3. Delete the DB row via attachmentRepo.DeleteAsync

OpenAttachmentAsync(attachmentId): per D-10 and RESEARCH.md — get attachment, verify StoragePath exists, call `Process.Start(new ProcessStartInfo { FileName = attachment.StoragePath, UseShellExecute = true })`. Throw NotFoundException if file missing.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| File picker → AttachmentService | User-selected file path enters the system; must validate before copy |
| AttachmentService → Filesystem | Filesystem writes for attachment storage; must prevent path traversal |
| AttachmentService → Process.Start | Opening attachments spawns external processes; must validate path is within managed directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 | Tampering | AttachmentService.AddAttachmentAsync — file extension spoofing | mitigate | Validate file extension against allowlist (.pdf, .jpg, .jpeg, .png) before copy. Per RESEARCH.md security domain: check magic bytes for PDF (%PDF), JPEG (FF D8 FF), PNG (89 50 4E 47) at the start of the file using a 4-byte header read. Reject mismatches. |
| T-03-04 | Tampering / Elevation | AttachmentService.AddAttachmentAsync — path traversal via filename | mitigate | Use `Path.GetFileName(sourceFilePath)` to strip directory components from user-supplied filename. Storage path is constructed exclusively from trusted root (`_attachmentRoot`) + sanitized documentId (int) + timestamp prefix + safe filename. No user-supplied path segments reach File.Copy destination. |
| T-03-05 | Denial of Service | AttachmentService.AddAttachmentAsync — oversized file | mitigate | Enforce 10MB (10_485_760 bytes) file size limit using `new FileInfo(sourceFilePath).Length` before File.Copy. Reject with ArgumentException if exceeded. |
| T-03-06 | Elevation | AttachmentService.OpenAttachmentAsync — arbitrary file open | mitigate | Before Process.Start, validate that `attachment.StoragePath` starts with `_attachmentRoot` (case-insensitive). If not, throw InvalidOperationException. This prevents opening files outside the managed attachments directory even if a corrupted DB row points elsewhere. |
| T-03-07 | Information Disclosure | AttachmentService.GetAttachmentsAsync | accept | All attachments for a document are visible to the single user. No multi-user access control needed. Accept risk. |
| T-03-SC | Tampering | dotnet restore (no new packages this plan) | accept | No new NuGet packages added — existing packages already audited |
</threat_model>
